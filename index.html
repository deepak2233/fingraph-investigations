    Meaning is part of the data model.
    
            
    
              OWL defines vocabulary and semantics. SHACL validates records.
              SPARQL retrieves explicit relationships. These solve different
              problems.

    SEMANTICS
    
              
    Party → Person / LegalEntity
    
              
    
                Account → heldBy → Party
    Transaction → sender / receiver →
                Account
    OwnershipAssertion → owner / ownedEntity /
                percentage / supportedBy
              
    
            
    
            
    
              
    VALIDATION
    
              
    Fail before investigation
    
              
    
                Transactions require positive decimal amounts, one sender and
                receiver, a three-letter currency, a typed timestamp, and a
                source ID. Ownership assertions require supporting evidence.
              
    
            
    
            
    
              
    EPISTEMIC BOUNDARY
    
              
    Unknown stays unknown
    
              
    
                Missing ownership creates a data gap. A name similarity creates
                a candidate. A graph pattern creates a lead. None establishes a
                crime, a legal UBO determination, or a confirmed sanctions
                match.
              
    
            
    
          
    
          
    
            
    Source-backed direct ownership query
    
            
    PREFIX fg: <https://fingraph.example/ontology/>
SELECT ?account ?owner ?claim ?evidence WHERE {
  ?account a fg:Account ; fg:heldBy ?entity .
  ?claim a fg:OwnershipAssertion ;
         fg:ownedEntity ?entity ; fg:owner ?owner ;
         fg:supportedBy ?evidence .
}
    
            
    
              Neptune is not a built-in OWL reasoner. This prototype uses RDFLib
              and pySHACL with RDFS closure, not full OWL DL reasoning. FIBO
              alignment is a design proposal.
